# SHAJRetailProducts V1 Security Acceptance Matrix

Status: **IN PROGRESS**

## Authority boundary

- Central owns tenant identity, roles/permissions, POS registration, branch/store trust, offline-grant signing, canonical recovery authorization and tenant PostgreSQL authority.
- POSService is a small offline edge runtime. It verifies Central-issued grants, persists only local derived/session state required for offline operation, and must never become a tenant/permission/key authority.
- Frontend is presentation/orchestration only. Central browser credentials remain HttpOnly-cookie based and local POS access remains bound to the packaged POS local session/machine boundary.
- Security work must reuse already-certified Auth/Az, Store/Device, Inventory, Catalog, Database and Observability boundaries rather than introduce parallel security models.

## Release decision

**NOT YET RELEASE CERTIFIED.** Core tenant/store/device/token/session/recovery security is strongly covered; auth brute-force, browser cookie/CORS, bounded import/upload admission, production RabbitMQ credential safety, lockfile-enforced Backend/Frontend builds and non-floating Frontend production dependency specs have executable evidence. Backend #111 provides an honest dynamic-SQL and production-dependency audit baseline without claiming legacy structural interpolation is already safe; Backend #112 rejects invoice uploads whose actual PDF/PNG/JPEG signatures do not match the admitted content type; Backend #113 prevents production PostgreSQL TLS from silently disabling server-certificate verification; Backend #114 prevents production support-case notifications from silently using the development fallback mailbox; Backend #115 ensures the production container activates fail-closed production policy and drops root privileges before Central starts; Backend #116 prevents raw SQL text/literals from being emitted by production DB timing logs while retaining timing observability; and Backend #117 hardens the privileged platform-admin seed path against malformed identity, unsupported roles, weak/default passwords and unnecessary sensitive logging. Remaining V1 Security work is concentrated on dependency remediation/residual review, the 79-site structural-query and remaining path/config audit, and the final consolidated release gate.
